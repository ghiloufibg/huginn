# M2 — Service logs screen

**Goal:** Enter on a repository opens mockup board 3: the merged, live log stream of the repository's **application containers only**, rendered as Spring Boot console lines, with the time-window switcher, follow/pause, pod scope, zoom on one entry and fullscreen. It stays smooth on chatty pods and never loses the user's place.

## Out of scope for M2
Level and text filters, highlight, full status-bar filter segments, help overlay (M3); real cluster streams (M4, same port); previous-container logs `P`, diagnostics, error groups, trace view `v`, sparkline, bookmarks, copy/export, redaction (M5).

## 1. Log decoding and rendering (driven adapters, config-driven)
- **`adapters/driven/logformat`** implements `ports.LogDecoder`:
  - `json-fields`: applies a `log_formats` profile — candidate JSON paths per canonical field (dots walk objects, first present wins), `level_aliases`, `hidden` globs. Hidden fields (Kubernetes enrichment) go to `LogEntry.Hidden`, other extra fields to `Fields`, stack traces to `Stack`. Timestamp parsed as RFC 3339 / epoch millis, falling back to the source time.
  - Non-JSON lines inside a JSON profile (Spring banner, JVM crash output) fall back to the `plain` decoder.
  - `plain`: recognizes the Spring Boot / Logback console layout (`time LEVEL pid --- [app] [thread] logger : msg`) and common `LEVEL`-prefixed lines; otherwise `LevelUnknown`, message = raw text.
  - Never fails, never drops a line; malformed JSON is shown raw.
- **`adapters/driven/springlayout`** implements `ports.LogRenderer`: `spring-compact` (`time LEVEL [thread] logger : message`, thread 15 and logger abbreviated to ~30 like Logback's `%logger{39}`) and `spring-full` (adds PID, `---`, `[app]`). Segments carry roles; the TUI maps roles to theme styles. Timestamp modes: local (default, `HH:MM:SS.mmm`), UTC, relative (`-12s`), none.
- Both registered by name in bootstrap (`logs.format` → profile → decoder; `logs.renderer`).

## 2. Core
- **`domain.LogBuffer`**: bounded ring buffer (default 50 000, `logs.buffer_lines`) of `LogEntry` with monotonically increasing `Seq`, a dropped counter, and index access by sequence so views survive eviction. Benchmarked at ≥ 100k appends/s.
- **`app.LogSession`** implements the driving port `ports.LogSession` (signature finalized now):
  - Resolves the repository's workloads from the current catalog snapshot, watches their pods (`WatchPods` with each workload's selector) and opens **one stream per application container** (`domain.ContainerFilter`), `timestamps` on, with the window (`sinceSeconds` / `tailLines`) and `follow`.
  - **History**: collects each container's window, then k-way merges by timestamp (stable by pod) and emits it at once, so the first screen is complete and ordered.
  - **Live**: lines enter a **reorder window of 250 ms** before being committed, so interleaving across pods is correct; committed lines are never reordered.
  - **Rollouts**: pods appearing during the session get a stream from their start; deleted pods are marked `terminated` and their lines kept.
  - **Reconnect** with backoff (1s, 2s, 5s, 10s, 30s) when a stream ends unexpectedly and the pod still exists; resumes with `since` = last line time to avoid duplicates (duplicates at the boundary are dropped by (time, text) equality).
  - **Retention notice**: for `since` windows, when a container that started before the window start returns its first line more than 1 minute after the window start, the session emits `logs of <pod> available from HH:MM only` (never invented: it only reports what was received).
  - Emits **batches** (`{Entries, Pods, Notices, HistoryDone}`) at most every 33 ms (≈30 fps), decoded through the configured `LogDecoder`.
- Driving port change: `LogSession.Open(ctx, LogQuery) (<-chan LogBatch, error)`; `LogQuery{Env, Repo, Window, Follow}`; pod scope is a view concern (no refetch).

## 3. TUI — logs screen (mockup board 3)
- **Layout**: header · one **pod strip** (pods with short id colored per pod, status word, restarts, version, `new`/`terminated` tags, scope) · log viewport · status bar. `F` fullscreens the viewport (pod strip hidden); `Esc` exits fullscreen, then goes back.
- **Viewport**: virtualized over the buffer (renders visible rows only), row = mark gutter + pod id + rendered segments; ERROR rows light red background, WARN rows light amber (theme roles); folded stack traces show the exception line and `+N lines, enter to open`. Wrap off by default with `←/→` and `H/L` panning; `W` toggles wrap.
- **Follow and pause** (no silent mode change, status chip always shows it):
  - `f` toggles follow (re-opens the session with or without `follow`); default **on**.
  - `space` pauses the view: lines keep buffering, chip shows `PAUSED +N`; resume jumps to live.
  - Scrolling up while live keeps streaming but stops auto-scroll (`LIVE · +N below`); `G` returns to the tail.
- **Time window**: `t` cycles presets, `T` opens the picker popup, `1`…`7` = 15m 30m 40m 45m 1h 1d 2d, `0` = tail (AZERTY aliases). Changing it reloads the session; status bar shows the window.
- **Pod scope**: `Tab` cycles all pods → each pod → all; `S` opens the pod selector fullscreen (list, `space` toggle, `a` all, `/` select by name pattern, `enter` apply) for many-pod services.
- **Order** `o` newest/oldest first. **Timestamps** `c` local/UTC/relative/none. **Pod id** `I` short/full/none.
- **Navigation**: `j/k`, `pgup/pgdn`, `g/G`, mouse wheel, `>`/`<` next/previous ERROR line.
- **Zoom** `Enter` (mockup board 6): entry in full — metadata line, full timestamp and all layout fields, message, `FIELDS`, `STACK TRACE` (own frames bold, framework frames dimmed; own = not under `java.`, `jdk.`, `sun.`, `jakarta.`, `org.springframework.`, `org.apache.`, `io.netty.`, … configurable later), `CONTEXT` (3 entries before/after of the same pod), `[+] kubernetes metadata` (toggle with `enter`/`space`); `p` switches to pretty raw JSON; `J`/`K` previous/next entry; scrollable; `Esc` back.
- **Status bar**: chip (`LIVE` / `LIVE +N below` / `PAUSED +N` / `STOPPED`) · window · scope · levels `all` (filters in M3) · order · `shown/total` · `buffer n%` · `dropped n` · notices (retention, stream reconnecting). Key hints right, dropped first when narrow.
- Rendering stays ≤ 30 fps: batches drive redraws; no render per line.

## 4. Bootstrap and config
- Decoder from `logs.format` profile, renderer from `logs.renderer`, `app.LogSession` with the catalog as pod source, container filter, clock, buffer size, window presets from `logs.tail_lines`, default window from `--since` / `logs.default_window`.
- Demo: default `demo.rate` raised to 1 line/s/pod so the stream feels alive; unchanged determinism.

## 5. Tests
- Decoder: logstash profile (nested paths, first-present wins, aliases, hidden globs to `Hidden`, stack to `Stack`, epoch and RFC 3339 times), custom profile from YAML, non-JSON fallback, Spring console lines, malformed JSON. Benchmark ≥ 50k lines/s.
- Renderer: golden segments for compact/full × timestamp modes; logger/thread abbreviation.
- Buffer: wrap-around, dropped counter, access after eviction; benchmark.
- Session (FakeCluster + FakeLogSource + FakeClock): only app containers streamed; history merged in time order across pods; live reorder window; new pod picked up; deleted pod marked terminated with lines kept; reconnect after stream error without duplicates; retention notice; batches coalesced; ctx cancel closes everything (no goroutine leak).
- Session over the **demo** cluster (bootstrap test): payment-service history is ordered and contains only app containers; the live rollout adds the new pod's banner lines.
- TUI goldens: logs 160×45 live, 80×24, wrapped, fullscreen, zoom (Java stack trace + context + collapsed metadata), window picker, pod selector; model tests: pause buffering count, auto-scroll lock and `G`, window keys incl. AZERTY, `Tab` scope, order, error jumps, zoom `J/K`.

## 6. Decisions to record
Follow on by default; 250 ms reorder window; session-level decoding; retention notice rule; stack folding representation; compact layout hides PID/app; pause vs scroll-lock semantics; own-frame heuristic; demo rate.

## Acceptance criteria
- From the services screen, Enter on payment-service shows its merged app-only logs (no istio/vault lines) in Spring layout within 1 s; `f`, `space`, `t`/`T`/digits, `Tab`, `o`, `c`, `I`, `W`, `F`, `Enter`/`Esc` behave as above and every mode change is visible in the status bar.
- During the live rollout the new pod appears in the pod strip and its Spring banner shows up in the stream; the retired pod is marked terminated and its lines stay.
- `2d` window in demo shows the retention notice.
- At a synthetic 10 000 lines/s the UI stays responsive (renders ≤ 30 fps, buffer bounded, dropped counter increases).
- Tests, lint, architecture test and CI green.
