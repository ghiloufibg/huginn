# M0 — Skeleton, config, ports, demo cluster, CI  (status: done)

**Goal:** a buildable, tested, lint-clean Go project whose layers and extension points are in place, so M1+ only adds behavior. `huginn --demo` starts, shows the app shell (header + status bar from the mockups) and quits with `q`.

## Out of scope for M0
Services table and logs screen (M1/M2), real Kubernetes adapter (M4, stubbed now; client-go not yet imported), goreleaser (M6).

## Work items
1. **Module & tooling** — `go.mod`, `.golangci.yml` (govet, staticcheck, errcheck, revive exported-doc rule, depguard per layer, gofumpt), `Makefile` (`test`, `lint`, `build`, `demo`, `cross`), `.editorconfig`, `.gitignore`.
2. **Domain (pure, stdlib)** — `Env` (dev/rec/prprd/prd + custom names allowed by config), `Repo`, `Workload`, `Pod`, `Container{Name, Image, Init, Sidecar}`, `ContainerState`, `Level` (Debug/Info/Warn/Error/Unknown + parse aliases), `LogEntry` (time, pod, container, level, logger, thread, message, stack, fields, raw), `TimeWindow` (15m…2d, tail N; `Parse`, `Presets`, `Next`), domain error kinds (`ErrUnauthorized`, `ErrForbidden`, `ErrUnreachable`, `ErrNotFound`, `ErrNotImplemented`).
3. **Ports** — driven: `ClusterClient` (list/watch pods and workloads per env+namespace, events for a pod), `LogSource` (open a stream for pod/container with since/tail/follow/previous → channel of raw lines with timestamps), `LogDecoder`, `LogRenderer`, `ManifestScanner`, `RepoResolver`, `SecretsProvider`, `Clock`; driving (signatures only): `ServiceCatalog`, `LogSession`, `Diagnostics`. Generic `Registry[T]` (`Register(name, factory)`, `Build(name, cfg)`, clear error listing known names).
4. **Fakes & contract suites** — `portstest.FakeCluster`, `FakeLogSource`, `FakeClock`, `FakeSecrets`; `portstest.RunClusterContract(t, factory)` and `RunLogSourceContract(t, factory)` reused later by the Kubernetes adapter.
5. **Config** — structs mirroring the spec plus D-017 profiles (`log_formats`, `manifests`, `environments[*].context/namespaces`, `containers`, `secrets`, `ui`). Load order: defaults → file → `HUGINN_*` env → flags. File lookup: `--config` → `$HUGINN_CONFIG` → `os.UserConfigDir()/huginn/config.yaml` (XDG on Linux, `~/Library/Application Support` on macOS, `%AppData%` on Windows; `~/.config/huginn` also accepted). Strict: unknown keys fail with a "did you mean" suggestion and line number. Validation collects all errors at once. `huginn config example` prints the documented sample; `huginn config validate [path]`; JSON schema generated by `go generate`, CI checks it is up to date.
6. **CLI** — `huginn [env]`, `-e/--env`, `--repo`, `--since`, `--config`, `--demo`, `--theme light|accessible|classic|none`, `--log-level`, `--version`. Env precedence: flag > positional > `HUGINN_ENV` > `default_env` > `rec`; flag and positional disagreeing is an error. `NO_COLOR` forces theme `none`. Version injected with `-ldflags`.
7. **Diagnostics log** — enabled by `HUGINN_DEBUG=1` or `--log-level`; file at `os.UserCacheDir()/huginn/huginn.log`; never writes to stdout/stderr while the TUI runs; secrets never logged (redacting handler for known keys).
8. **Demo adapter** — implements `ClusterClient` + `LogSource`, deterministic (seed + injected clock):
   - the 14 repos of the prototype across dev/rec/prprd/prd, one namespace per env on one cluster (matches the real topology);
   - pods with `istio-proxy`/`vault-agent` sidecars and `istio-init` init containers (to exercise filtering later);
   - scenarios: healthy, CrashLoopBackOff with previous-container logs, OOMKilled, ImagePullBackOff, Pending, a rollout that replaces pods during the session, an error burst;
   - log lines emitted as **logstash-logback JSON with Kubernetes enrichment fields** (the real shape to decode), plus a few non-JSON lines (Spring banner, JVM crash) and multi-line stack traces;
   - history for the window + live generation at a configurable rate (default realistic, `--demo-rate` hidden flag for stress).
9. **Bootstrap** — builds `ClusterClient`/`LogSource` from `cluster.client: demo|kubernetes` (`--demo` forces demo), wires config, clock, diag logger, TUI.
10. **TUI shell** — Bubble Tea v2 program with the light theme tokens, one-line header (app, env tag, context/namespace, breadcrumb, auth/sync) and one-line status bar exactly as in the mockups; `q`/`ctrl+c` quit, resize handled; placeholder body "services screen arrives in M1". Theme structure (light/accessible/classic/none) and keymap type defined, keymap remapping wired from config.
11. **Architecture test** — parses imports of every package under `internal/` and enforces ARCHITECTURE.md rules (core → stdlib only + core; adapters never import each other; only bootstrap imports adapters). Includes a negative test on a fixture to prove it catches violations. Mirrored by depguard in golangci-lint.
12. **CI (GitHub Actions)** — `ci.yml`: matrix ubuntu/macos/windows: `go vet`, `go test ./...` (`-race` on Linux), `golangci-lint` via the official action, cross-build `CGO_ENABLED=0` for linux/darwin/windows × amd64/arm64, `govulncheck`, schema freshness check.
13. **Docs** — `README.md` (what it is, status, build, `--demo`), `docs/ARCHITECTURE.md` updated with the concrete packages, `docs/DECISIONS.md` D-021, `CLAUDE.md` commands.

## Acceptance criteria
- `go build ./...` and cross-builds for 6 targets with `CGO_ENABLED=0` succeed.
- `go test ./...` and `golangci-lint run` are green locally and in CI on the three OSes.
- `huginn --version`, `huginn config example | huginn config validate -`, and `huginn --demo` (shell renders, `q` quits, resize OK) work.
- Adding an import of an adapter from `internal/core` makes the build fail.
