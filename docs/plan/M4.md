# M4 — The real cluster: a Kubernetes adapter, tested on a local lab  (status: plan)

**Goal:** `huginn --config <folder> rec` works against a real cluster (GKE in production, kind or minikube locally) with the same screens as `--demo`. Everything stays strictly read-only.

**Explored first**: a local cluster was run in Docker with dummy workloads (`deploy/lab/`), and the Kubernetes API was probed for every behaviour the adapter relies on. The findings shaped this plan; the bugs they revealed are listed in §7.

## 1. The lab (done during planning, `deploy/lab/`)
- **Setup:** `deploy/lab/up.sh` starts a kind cluster in Docker (or minikube with `up.sh minikube`), loads two public images (alpine, nginx) and applies `workloads.yaml`, a dummy estate with one workload per state Huginn shows:
  - healthy with a sidecar and an init container;
  - two workloads of one repository;
  - CrashLoopBackOff, OOMKilled, ImagePullBackOff and Pending (Unschedulable);
  - nginx text logs;
  - a StatefulSet in a second environment.
- **Logs:** a shell generator writes Spring-style logstash JSON with stack traces.
- **Permissions:** `rbac.yaml` adds a read-only identity limited to one namespace, for the "forbidden" paths.
- **Huginn config:** `deploy/lab/config/` is the config folder for it (validated in CI with the examples).
- **Why kind rather than minikube here:** minikube could not start in this sandbox (§7, environment issues). The manifests and `up.sh minikube` work on a normal Docker host.

## 2. The adapter: `internal/adapters/driven/kubernetes` (client-go)

| Port method | Implementation |
|---|---|
| `ListWorkloads` / `WatchWorkloads` | Shared informers **per namespace** (D-004: no cluster-wide RBAC needed) for Deployments, StatefulSets, DaemonSets and CronJobs. The watch sends the current state as Added events, then changes. |
| `ListPods` / `WatchPods` | Pod informer per namespace; the selector is applied in the lister. |
| `PodEvents` | On demand: `events` list with the field selector `involvedObject.name=<pod>` (measured working with the restricted identity). |
| `Stream` (LogSource) | `pods/log` with `timestamps=true`, `container`, `sinceSeconds` or `sinceTime`, `tailLines`, `follow`, `previous`. Each line is split into the RFC 3339 nano timestamp and the text. |

Conversions measured on the lab:
- **Owners:** a pod is owned by a **ReplicaSet**, whose owner is the Deployment. The adapter resolves the chain from the ReplicaSet lister, so `Pod.OwnerName` is the workload, as the domain expects. StatefulSet and DaemonSet pods are owned directly. CronJob pods go Job → CronJob.
- **Container state:** state, reason, message, restarts and last termination (reason, exit code, time) map one to one onto `domain.Container`. OOMKilled appears as `waiting: CrashLoopBackOff` + `lastState.terminated: OOMKilled/137`, which the domain already reads as OOMKilled.
- **Pending pods:** `status.conditions[PodScheduled].reason/message` (`Unschedulable: 0/1 nodes are available: 1 Insufficient memory…`) maps to `Pod.Reason/Message`.
- **Rollouts:** `replicas`, `updatedReplicas`, `readyReplicas`, the Progressing condition, and `observedGeneration < generation` while the controller has not yet seen a change.
- **Events:** normalized (see bug B6): `LastSeen = lastTimestamp ?? series.lastObservedTime ?? eventTime`, `Count = count ?? series.count ?? 1`.
- **Errors:** mapped to domain kinds:
  - 401 → `ErrUnauthorized` with the gcloud fix-it message;
  - 403 → `ErrForbidden` per namespace (the other namespaces keep working, as the catalog already supports);
  - 404 → `ErrNotFound`;
  - 400 "container … is waiting to start" → a new `ErrNotStarted`;
  - network errors → `ErrUnreachable`;
  - missing kubeconfig context → `ErrConfig` (permanent, see B8).

Connection:
- **kubeconfig:** loaded with `clientcmd` default loading rules (`KUBECONFIG`, `~/.kube/config`), with the context of each environment (`environments.yaml`). One clientset per context, shared by environments that use the same context.
- **GKE authentication:** by the user's existing `gke-gcloud-auth-plugin` (exec credential plugin, already in their kubeconfig). Huginn never logs in.
- **Proxy:** `HTTPS_PROXY`/`NO_PROXY` and the extra CA bundle (`SSL_CERT_FILE`) work through the standard transport.
- **Client settings:** client-side rate limits raised moderately (QPS 20, burst 40) and a user agent `huginn/<version>`.
- **Read-only by construction:** the adapter only calls `get`, `list`, `watch` and `pods/log`. A test lists every verb it can reach (a fake clientset records actions) and fails on any write verb.

Cost: client-go takes the binary from 8.8 MB to about 35 MB (measured with a probe program). This is accepted (`kubectl` is about 50 MB) and recorded in D-034.

## 3. Changes outside the adapter (from the lab findings)
1. **Resume without duplicates (B2).** The API's `sinceTime` has **second** precision. After a reconnect, the tailer must drop every line strictly before the last delivered time and de-duplicate only the lines at that exact time. The contract suite gains a "second-precision sinceTime" case, and the fake log source gains that mode, so every LogSource is tested for it.
2. **Waiting containers (B3, B4).**
   - **End of stream:** a follow stream that ends without error while the pod watch shows the container *waiting* (CrashLoopBackOff, ContainerCreating) is not "unreachable". The pod strip shows `waiting: CrashLoopBackOff`. The tailer waits for the container's `restartCount`/state to change (from the pod watch) instead of hammering the API with back-off reconnects that replay the same lines.
   - **Not started:** "waiting to start" (400) becomes `ErrNotStarted`, shown as `not started: ImagePullBackOff`, and retried on the next pod update.
3. **Previous instance (`P`, planned since M2).** The lab shows `--previous` is what explains a crash loop. The logs screen gets `P` on a pod: the previous instance's logs of its app containers, labelled "previous instance".
4. **Long lines (B5).** Lines are read with a `bufio.Reader` capped at 1 MiB per line: longer lines are truncated with a notice, never an error that stops the stream. The lab measured a 40 KB line delivered whole by the API.
5. **Permanent errors are not retried (B8).** The catalog stops retrying on `ErrConfig` and `ErrNotImplemented` (unknown context, adapter missing). The screen says what to fix instead of "retrying automatically".
6. **No terminal (B1).** Without a TTY, Huginn says "huginn needs an interactive terminal" and exits with code 2, not the raw Bubble Tea error.
7. **`namespace_from`** (sops) resolved when an environment is opened, with the sops error reported against `environments.yaml`.
8. **The manifests rule** of `services.yaml`: scan `repos_root/*/<overlay_glob>` with the Kustomize entry files (resources, names, namePrefix/Suffix), cached per repository. It is optional, and after the rest it is the first thing to cut if M4 grows.

## 4. Tests
- **Unit** (fast, in CI):
  - adapter conversions on client-go fake clientsets: owners chain, states, events normalization, error mapping, verbs used;
  - the timestamp line splitter, long lines;
  - the tailer's second-precision resume and waiting containers.
- **Contract:** `RunClusterContract` and `RunLogSourceContract` (with the new second-precision case) against:
  - the demo adapter, in CI as today;
  - the Kubernetes adapter on the lab, behind `HUGINN_LAB=1`.
- **End to end on kind in CI:** a new GitHub Actions job (ubuntu runners have cgroup v2 and Docker) runs `deploy/lab/up.sh`, waits for the workloads, then:
  - runs the contract suites against the lab;
  - drives `huginn --config deploy/lab/config rec` in a pseudo-terminal: services screen rows and statuses, then the logs of `payment-service` (JSON decoded, sidecar hidden, stack folded), a crash-loop pod labelled waiting, a rollout restart seen live, and the forbidden namespace of the `restricted` environment reported without breaking the other.
- **Manual on GKE** (the user): a short checklist in the README; auth plugin, a production namespace, `namespace_from`.

## 7. Bugs and issues encountered

### Huginn (to fix in M4)

| # | Severity | Where | What happens | Found by |
|---|---|---|---|---|
| B1 | low | bootstrap / tui.Run | Without an interactive terminal Huginn prints `bubbletea: error opening TTY: … no such device or address` | running in a pipe |
| B2 | **high** | core/app tailer (resume) | `sinceTime` has second precision on the real API. After a reconnect, lines of the same second before the last delivered line are **shown twice**: they are before `SinceTime` but not in the de-duplication set, which only holds lines at the exact last time. The demo and the fake honour nanoseconds, so tests missed it | `kubectl logs --since-time=…07.881Z` returned lines from `07.276` |
| B3 | medium | core/app tailer | A follow stream on a container in CrashLoopBackOff ends at once **without error** after replaying the last instance. The tailer treats that as "unreachable", shows `no logs: unreachable` and reconnects in a loop, replaying the same lines (also duplicated, see B2) | `kubectl logs -f` on the crash-looping pod ended after 1 s |
| B4 | medium | error mapping | Logs of a container that has not started (ImagePullBackOff, ContainerCreating) fail with HTTP 400 "is waiting to start"; there is no domain error kind for it, so it would show as an unknown error | `kubectl logs` on the image-pull pod |
| B5 | medium (latent) | future log reader | The API delivers a 40 KB line whole (the runtime's 16 KiB split is reassembled). A `bufio.Scanner` with its default 64 KiB limit would stop the stream on the first large payload | 40 000-character line in the lab |
| B6 | low (latent) | future events conversion | New-style events have no `count` and no `lastTimestamp` (only `eventTime`, sometimes `series`); read naively, they would show as undated, count 0 | `Scheduled` event of the lab |
| B7 | low | domain version | A `rollout restart` keeps the image, so the version column cannot show it (WHY still says `rollout 3.20: 1/2 updated`). Proposed: show the ReplicaSet revision when the image did not change | `kubectl rollout restart` in the lab |
| B8 | low | UX | The services screen of an unavailable cluster client says "retrying automatically" for a **permanent** error (adapter not implemented; will be the same for an unknown kube context) | running today's build on the lab |

### Tooling and environment (not Huginn; worked around in `deploy/lab`)

| Issue | Cause | Workaround |
|---|---|---|
| minikube cannot pull its control plane | This environment's network policy denies `registry.k8s.io`, and minikube's containerd preload did not contain the images | kind (node image from Docker Hub). On a normal machine minikube works (`up.sh minikube`) |
| Node containers fail with `oom_score_adj: Permission denied` | Nested containers cannot lower OOM scores | containerd `restrict_oom_score_adj = true` (in `kind.yaml`; minikube rewrites its containerd config at every start, so it cannot keep it) |
| Kubelet refuses to start on cgroup v1 | Kubernetes ≥ 1.35 fails cgroup v1 hosts by default | `failCgroupV1: false` (in `kind.yaml`) |
| Kubelet: `missing paths: /sys/fs/cgroup/hugetlb/kubelet.slice` | The host has no `hugetlb` controller | pre-create the slice directories (README) and use Kubernetes 1.33 in this sandbox |
| TLS errors pulling from inside the node | The sandbox proxy intercepts TLS | minikube: CA in `~/.minikube/certs`; kind needs no pulls |
| `kind load docker-image` fails: `content digest … not found` | Docker 29 exports multi-platform indexes whose other platforms are absent | `docker save --platform linux/amd64 … \| ctr images import --platform linux/amd64 -` (in `up.sh`) |
| `docker cp` into the kind node's `/tmp` silently does nothing | `/tmp` is a tmpfs in the node | pipe through `docker exec -i` |
