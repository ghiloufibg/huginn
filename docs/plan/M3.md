# M3 — Level filter, live text filter (filter / highlight), status bar, help  (status: done)

**Goal:** on the logs screen (mockup board 4), narrow thousands of lines to what matters in a few keystrokes, without reloading: filter by level, grep live as you type, switch between **filter** (hide non-matching) and **highlight** (keep all, jump between matches), use regex, invert, stack several filters, show context lines. Every mode change is visible at once in the status bar, and `?` / `F1` explains every key of the current screen.

## Out of scope for M3
Trace pivot `v`, error groups, bookmarks, copy/export, redaction (M5); saved filters per repo (V2).

## 1. Core — filter engine (`internal/core/domain`, pure, benchmarked)
- **`TextFilter`** `{Pattern, Regex, Invert}`: case-insensitive substring by default; regex mode compiles with `(?i)`; an invalid regex returns an error (the UI keeps the last valid filter and shows why). A leading `!` in the typed text means invert (`!health`), `\!` escapes it.
- **What is searched**: message, logger, thread, trace id, visible fields (keys and values) and the stack trace — never the hidden Kubernetes metadata. The raw line is searched for unstructured entries.
- **`LogFilter`** `{Levels LevelSet, IncludeUnknown, Texts []TextFilter (AND), Mode Filter|Highlight, Context int}` with:
  - `Visible(entry) bool` (levels + texts in filter mode; levels only in highlight mode),
  - `Matches(entry) bool` (texts),
  - `Ranges(s string) [][2]int` (match positions in a rendered segment, for highlighting; inverted filters highlight nothing),
  - `Apply(entries) []Row` expanding **context**: `N` entries before/after each match, marked as context, with a separator between non-contiguous groups.
- Benchmark: filtering 50 000 entries with a substring < 20 ms, with a regex < 50 ms (the view is recomputed on each keystroke; incremental for appended entries).

## 2. TUI — levels (mockup board 4, popup)
- `l` opens the level picker: `[x] ERROR`, `[x] WARN`, `[x] INFO`, `[x] DEBUG`, `[x] unknown (no level detected)`; `space` toggles, `enter` applies, `esc` cancels.
- Quick keys: `e` errors only, `w` warn + error, `a` all levels (incl. unknown).
- Status bar: `levels all` or `levels WARN ERROR` (+ `unknown` when included).

## 3. TUI — live text filter (mockup board 4, prompt line)
- `/` or `ctrl+f` opens the prompt above the status bar: ` / gateway|redis_   HIGHLIGHT  REGEX  case-insensitive      match 2 of 5 …`.
- **Incremental**: the view updates as you type (debounced to one recompute per frame).
- `x` (outside the prompt) and `ctrl+x` (inside) switch **filter ⇄ highlight**; `ctrl+r` toggles regex; `!` prefix inverts; `ctrl+a` adds the current text as a stacked filter and starts a new one (AND); `enter` keeps the filters, `esc` in the prompt cancels the edit, `esc` on the stream clears the last filter.
- **Highlight mode**: matches highlighted (theme highlight style + underline, so it is visible without color), `n` / `N` next/previous match, status `match i of n`.
- **Filter mode**: non-matching entries hidden; **context** `X` cycles 0 → 1 → 3 → 5 lines around matches (context lines dimmed, `--` between groups).
- Invalid regex: prompt shows `invalid regex: …` and the previous valid result stays.
- New live lines are tested against the filter as they arrive (no full recompute).
- `>` / `<` (next/previous ERROR) and zoom keep working on the filtered view.

## 4. Status bar and mode-change feedback
- Status bar segments (logs): chip · window · scope · levels · filters (`filter /gateway|redis/ HIGHLIGHT`, `+1 more`, `!` for inverted) · context · order · `shown/total` · buffer · dropped · notice.
- **Flash**: every mode-changing key shows a short confirmation in the status bar for 2 s (`wrap on`, `timestamps UTC`, `pod id full`, `newest first`, `follow off`, `levels WARN ERROR`, `regex on`…), satisfying "no silent mode change".
- Narrow terminals keep the chip, filters and counts first; hints go before state.

## 5. Help overlay
- `?` or `F1` on every screen (services, logs, zoom, pod selector) opens a fullscreen help: **this screen** then **global**, grouped (move, time and stream, filter, inspect, display), each line `key(s) → action`, generated from the **live keymap** (remapped keys show as remapped) and a single table of action descriptions.
- `/` inside the help filters its lines; `esc` closes.
- Key hints on the right of the status bar come from the same table, so hints, help and README cannot disagree.

## 6. Tests
- Domain: substring/regex/case, invalid regex, `!` invert and `\!` escape, stacked AND, levels with and without unknown, fields and stack searched but hidden metadata not, match ranges (overlaps, unicode), context expansion with separators and edges; benchmarks.
- TUI goldens: filter prompt editing (highlight + regex), filter mode with context lines, level popup, highlight with `match i of n`, help for services and for logs, invalid regex prompt, narrow 80×24 status bar with filters.
- TUI model tests: typing updates counts live; `x` toggles; `ctrl+r`; `!`; `ctrl+a` stacks and `esc` pops; `n`/`N` wrap; `e`/`w`/`a`; new batch filtered incrementally; flash appears and expires; `?` opens and filters help on each screen; remapped key shown in help.

## 7. Decisions to record
Invert is the `!` prefix only (`ctrl+i` is `tab` in terminals, and `i` is text inside the prompt); context key `X` (the `-`/`+` keys collide with AZERTY number-row aliases); searched fields; debounce policy; flash duration.

## Acceptance criteria
- In the demo, `/` then typing `timeout` on payment-service narrows the stream live; `x` switches to highlight with `match i of n` and `n`/`N` move; `ctrl+r` with `gateway|redis` works; `!health` hides health lines; `ctrl+a` stacks filters; `X` shows context lines; `e`, `w`, `a`, `l` work and show in the status bar.
- `?` / `F1` show correct, remap-aware help on every screen.
- Filtering 50 000 lines stays under a frame on keystrokes; live lines keep flowing through filters.
- Tests, lint, architecture test and CI green.
