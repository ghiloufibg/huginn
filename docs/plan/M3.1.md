# M3.1 — More room for log messages: optional columns and a key bar  (status: done)

**Goal:** give the message as much width as the developer wants, and make every useful key visible without leaving the logs screen, before starting M4.

## 1. Optional columns

The stream line today is `pod time LEVEL [thread] logger : message`. At 160 columns, pod + time + level + thread + logger take about 75 cells before the message starts; on a 120-column IDE terminal the message gets less than half the line.

### Columns and defaults
| Column | Default | Width | Notes |
|---|---|---|---|
| time | on | 12 | format still cycled by `c` (local, UTC, relative, hidden) |
| pod | on (short id) | 5–6 | `I` still cycles short / full / hidden |
| level | on | 5 | kept by default: it is the scan anchor (can be hidden) |
| thread | on | 17 | `[nio-8080-exec-7]` |
| logger (class) | on | ~31 | abbreviated `i.g.p.gateway.GatewayClient` |
| message | always | rest | cannot be hidden |

### Keys (all remappable, AZERTY/QWERTZ friendly, no digits: they stay window presets)
- **`C` — columns picker** (popup, applies live). Inside it, one letter toggles each column: `t` time · `p` pod · `l` level · `h` thread · `c` class/logger; `z` message only; `r` reset to defaults; `esc` closes. So "hide the thread" is `C` then `h`, and the popup shows the state of every column (no hidden state).
- **`z` — focus layout** directly on the stream: hides pod, thread and logger in one key (message right after time and level); `z` again restores the previous columns. This is the "maximum room" shortcut.
- `I` (pod id short/full/hidden) and `c` (timestamp format) keep working; hiding the pod or time from `C` is the same state as `I`/`c` reaching "hidden".
- Every toggle shows its confirmation flash (`thread hidden`, `focus layout on`), and the status bar shows `cols: time pod lvl` when not all default columns are shown.

### Automatic narrowing (default `auto`, overridable)
When the terminal is narrow and the user has not chosen columns yet in the session: below 140 cells the thread is hidden, below 110 the logger too. The first manual choice (`C`, `z`, `I`) turns the automatic mode off for the session.

### Where it lives
- `ports.RenderOptions` gets a `Columns` set (time, level, thread, logger, pid, app); `springlayout` renders only requested columns, keeping alignment. The pod prefix stays a TUI concern.
- Zoom always shows every field (full Spring layout): hidden columns are never lost, only hidden from the stream.
- Filters still search thread and logger even when their column is hidden (matches in a hidden column are counted; the zoom shows them).
- Config: `ui.logs.columns: auto` (default) or a list, e.g. `[time, level, message]`; `ui.logs.focus_columns` for what `z` keeps.

## 2. Key bar: where to show the keys

**Recommendation: a dedicated key bar on the bottom line, under the status bar; state stays in the status bar; the header keeps context only.**

Why bottom and not header:
- The header answers "where am I" (env, context, breadcrumb, connection). Keys answer "what can I do"; they belong next to where input happens — the filter prompt is already at the bottom, so its keys appear right above/below it.
- k9s shows keys in the header, but its block takes 5–6 lines; on a logs screen those are 5–6 log lines lost. One line at the bottom (nano / htop / Midnight Commander style) is cheaper and familiar.
- Today hints share the status bar with state and are the first thing truncated; separating them lets the status bar show all state.

### Behavior
- **Contextual**: the bar shows the keys of the current mode — stream, filter prompt (`ctrl+r regex  ctrl+x mode  ! invert  ctrl+a add  enter keep  esc cancel`), paused, zoom, popups (level, window, columns), services screen, help.
- **Three sizes, cycled by `F2`** (alternative `ctrl+k`, remappable): **compact** (1 line, default: the ~10 most useful keys) → **full** (2 lines, ~20 keys) → **hidden** (0 lines, maximum room; the status bar shows `F2 keys  ? help`). The choice is kept for the session and configurable (`ui.key_bar: compact | full | hidden`).
- **Format**: `key label` pairs separated by spaces, keys in the key style, labels dim, grouped by purpose (navigate · stream · filter · view); on narrow terminals lower-priority entries drop first; `? help` is always last and never dropped.
- **Single source**: entries come from the action table (`actions.go`) and the live keymap, like help, so remapped keys show correctly.
- Applies to every screen for consistency (services, logs, zoom, pod selector, help).
- `?` / `F1` still lists everything; the key bar is the short version.

## 3. Out of scope

## 4. Tests
- Renderer: every column combination keeps alignment; hidden level/thread/logger; unstructured lines unaffected.
- TUI goldens: default, focus layout, columns picker, key bar compact/full/hidden, filter prompt key bar, zoom key bar, 80×24 and 120×30 with automatic narrowing.
- Model tests: `C` letters toggle live, `z` round-trip restores the previous set, manual choice disables auto, `I`/`c` and the picker stay in sync, `F2` cycles and persists across screens, flashes, remapped keys appear in the key bar and help, filters still match hidden columns.
- Config: `ui.logs.columns` and `ui.key_bar` validation and schema.

## 5. Decisions to record
Key bar at the bottom (state and actions separated); `C` picker with inner letters instead of one global key per column (keeps the keyspace free for M5 features: `d`, `m`, `v`, `P`, `E`, `B`); `z` focus; automatic narrowing thresholds; `F2`/`ctrl+k`.

## Acceptance criteria
- On payment-service at 120 columns, `z` shows messages starting right after the level; `C` then `h` hides only the thread; `r` in the picker resets.
- The key bar shows the right keys in stream, prompt, paused and zoom modes; `F2` cycles compact → full → hidden; nothing overflows at 80×24.
- Tests, lint, architecture test and CI green.
