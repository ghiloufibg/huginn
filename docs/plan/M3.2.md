# M3.2 — Services screen that uses all the available space  (status: done)

## Problem (today, 160×30)
- **Right side wasted**: the table ends at column ~110; ~50 columns are blank.
- **Bottom wasted**: 15 rows in a 26-line body; ~11 lines are blank.
- **The "why" is missing**: `CrashLoopBackOff` says what, not why. The developer still has to open the repo to learn "exit 1 4m ago" or "0/6 nodes: insufficient memory".

## Principle
Fill space with **what the developer needs next**, in this order: (1) why a service is unhealthy, (2) the details of the selected service, (3) more rows. Never pad, never shrink what is already there. The layout is recomputed on every resize from a small set of breakpoints, so the screen is always full and never overflows.

## 1. A flexible WHY column (fills the width)
A new last column **WHY** takes all remaining width (min 24 cells, dropped first on narrow terminals). It is computed in the domain (`domain.Explain(summary)`) from data we already watch — no extra API calls:

| Status | WHY (examples) |
|---|---|
| CrashLoopBackOff | `catalog-indexer: exit 1 (Error) 4m ago · 23 restarts · back-off 5m` |
| OOMKilled | `order-orchestrator: OOMKilled exit 137, 38m ago · limit 1Gi` |
| ImagePullBackOff | `cannot pull document-renderer:v1.11.0 — manifest unknown` |
| Pending | `1 pod pending: 0/6 nodes available: insufficient memory` |
| Degraded | `2 of 3 pods not ready (readiness failing) · 7 restarts` |
| Progressing | `rollout v1.7.9→v1.8.0: 2/3 updated, 1 starting` |
| Healthy | dim, only when informative: `last restart 2h ago (OOMKilled)` |
| scaled to 0 | `scaled to 0` |

Data additions: `Container.Message` (waiting/terminated message from the pod status) and `Pod.Reason/Message` (e.g. `Unschedulable`), filled by adapters (demo now, Kubernetes in M4). The REPO column shrinks to its content; WHY truncates with `…` and shows in full in the preview.

## 2. A preview of the selected service (fills the height, or the side)
The selected repository's details are shown in the free space, updated as the cursor moves:
- **Workloads**: kind, name, ready/desired, updated, version(s).
- **Pods** (application containers only): short id, status, ready, restarts, last termination, node, age.
- **Recent warnings** of the worst pod (Kubernetes events, fetched on demand when the cursor rests 300 ms on a row, cached 30 s; never watched continuously — D-004): `2m  BackOff  Back-off restarting failed container (x87)`.
- **Hidden containers** line (sidecars).

### Placement (responsive)
| Terminal | Layout |
|---|---|
| width ≥ 200 | **side panel** on the right (~40% width), table on the left with WHY narrower |
| free lines under the table ≥ 8 | **bottom panel** in the free lines (never pushes rows off) |
| otherwise | no panel (table uses everything); `p` forces a bottom split (50%) |

`p` toggles the preview (auto → off → auto); `P`… stays free for M5. Enter still opens the logs.

## 3. Status groups when rows fit (optional polish)
When sorted by status and rows + group titles fit the height, rows are grouped under thin titles — `FAILING 3 · DEGRADED 2 · ROLLING 2 · HEALTHY 8` — so the eye jumps to problems. Groups disappear automatically when space is short (never costs a row).
