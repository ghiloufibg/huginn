# M1 — Services screen (home), statuses, navigation, environment switch

**Goal:** `huginn --demo` opens on a live services table that matches mockup board 1: one row per repository, status driven by the worst pod, updated by watches (no polling), fast keyboard navigation, name filter, sort, environment switch with the production banner. Enter opens the repo (logs placeholder until M2), Esc comes back.

## Out of scope for M1
Logs screen (M2), help overlay and full key-hint system (M3), real cluster, auth diagnostics and last-known-data cache (M4), `ctrl+p` fuzzy service finder (M5, V1 item 17), manifest-based repo resolution (M4).

## 1. Core — domain (pure, table-tested)
- **Container classification** `domain.ContainerFilter{Deny, Allow []string; IncludeInit bool}` with `IsApp(Container, workload string)`: init containers and the built-in + configured denylist (name or image substring) are auxiliary, the allowlist wins, and a container named like the workload is always the app container. Reused by M2 for log streams.
- **Pod status** `domain.PodStatus(Pod) ServiceStatus`, precedence worst first:
  1. a container waiting in `CrashLoopBackOff` → **CrashLoopBackOff**, except when its last termination was `OOMKilled` → **OOMKilled** (more actionable);
  2. a container terminated with `OOMKilled` → **OOMKilled**;
  3. waiting `ImagePullBackOff` / `ErrImagePull` / `InvalidImageName` → **ImagePullBackOff**;
  4. phase `Pending` (scheduling, container creating) → **Pending**;
  5. running but not ready → **Degraded**;
  6. otherwise **Healthy**. Phase `Unknown`/`Failed` → **Unknown**/**Degraded**.
- **Service summary** `domain.Summarize(repo, workloads, pods, filter) ServiceSummary`: status = worst of pod statuses and workload state (rollout in progress → **Progressing**; ready < desired without a worse pod → **Degraded**; desired 0 → **Unknown**, shown as "scaled to 0"); PODS = ready/desired summed over workloads; RESTARTS = sum over app containers; LAST RESTART = latest `LastTermination.At`; VERSION = image tag of the app container of the first workload, `old→new` during a rollout; AGE from the oldest workload.
- **Sorting** `domain.SortServices(rows, SortKey)`: `status` (worst first, then name), `name`, `restarts` (desc), `age` (newest first).

## 2. Core — app (use cases, tested with portstest fakes)
- **Repo resolvers** (pure, parameterized by config data, no company values in code): `MappingResolver` (explicit `repos:`), `LabelResolver` (configured label/annotation keys), `ChainResolver` (first match wins, keeps unassigned workloads). Manifest resolver arrives in M4 behind the same port.
- **`ServiceCatalog`** implementation `app.Catalog`: for an env, opens `WatchWorkloads` + `WatchPods` on the env's scope, keeps state, resolves repos, summarizes and emits a **snapshot** `{Services, Unassigned, UpdatedAt, Err}` on each change, coalescing bursts (at most one snapshot per 100 ms via the injected clock). A failing watch emits a snapshot with `Err` (domain error kind) and retries with backoff; rows of forbidden namespaces carry their own `Err` without hiding others. Driving port `ServiceCatalog.Watch` returns `<-chan CatalogSnapshot` (signature updated from M0).
- Contract: cancelling ctx stops watches and closes the channel (no goroutine leaks; checked with a leak test).

## 3. TUI
- **Screen router** in the root model: a small `screen` interface (update, view for a given size, breadcrumb, status-bar segments, key hints). Screens: `services`, `logsPlaceholder`. Overlays: `envPicker`. Esc pops back.
- **Services table** (reusable `table` component): virtualized rows (renders only visible lines), selection kept on the same repo across updates and re-sorts, `j/k/↑/↓`, `pgup/pgdn`, `g/G`, mouse wheel. Columns `REPO WORKLOADS PODS STATUS RESTARTS LAST-RESTART VERSION AGE`; REPO takes the free width; on narrow terminals columns drop in the order AGE, LAST RESTART, WORKLOADS, VERSION (never STATUS). Status words colored by theme, restarts ≥ 5 bold red, > 0 warning color. Unassigned workloads listed after repos, dimmed, with "(no repo)".
- **Filter** `/` or `ctrl+f`: prompt line above the status bar, live substring match (case-insensitive) as you type, Enter keeps it, Esc clears; status bar shows `filter <text>`.
- **Sort** `s` cycles status → name → restarts → age; shown in the status bar.
- **Refresh** `r`: restarts the watches; status bar shows `resyncing` until the next snapshot.
- **Environment switch** `ctrl+e`: popup listing configured envs with context/namespace and a PRODUCTION label; Enter switches (cancel old watch, start new), header and banner update, status bar notes `switched rec -> prd at HH:MM:SS` (no silent mode change).
- **Header**: env tag, context / namespace(s), breadcrumb, and connection state on the right: `connecting…`, `watching · synced HH:MM:SS`, or `error: <kind>`.
- **Status bar**: `SERVICES` (or `PRODUCTION`) chip, `N repos · x failing · y degraded/pending · z rolling · w healthy`, sort, filter; key hints right (`enter logs  / filter  s sort  ctrl+e env  q quit`).
- **Enter** opens `services / <repo>` placeholder ("logs arrive in M2") showing the repo's pods and their statuses from the snapshot, to validate data flow; `--repo` opens it directly once the first snapshot contains the repo (error in status bar if it never appears).
- **Watch errors**: whole-screen message with the error kind and `r` retry (the full actionable error screen is M4); per-row errors shown in the STATUS column as `error: forbidden`.
- Bubble Tea plumbing: a command that waits for the next snapshot and re-arms itself; snapshots already coalesced by the catalog, so rendering stays under ~10 fps on this screen.

## 5. Tests
- Domain: pod status precedence table (every rule and tie), summarize (rollout versions, scaled to 0, restarts only from app containers), sorting stability, container filter (deny, allow, init, image substring, workload-name match).
- App: resolvers (mapping beats labels, first label key wins, unassigned kept), catalog with `FakeCluster` + `FakeClock` (initial snapshot, pod update propagates, deletion, coalescing, watch error → Err snapshot + retry, ctx cancel closes channel), plus the catalog over the **demo** adapter reproducing the mockup (3 failing, 2 degraded/pending, 2 rolling…), and the live rollout turning payment-service Progressing then Healthy `v2.14.4`.
- TUI goldens (ANSI stripped): services 160×45 (rec), 80×24 (columns dropped), prd with env popup, active filter, placeholder repo screen, watch-error screen. Model tests: navigation bounds, selection kept across re-sort and updates, filter editing, sort cycle, env switch cancels the previous watch, Esc/back, `--repo` jump.
- Benchmark: summarizing 500 repos / 3 000 pods under 5 ms.

## 6. Decisions to record
Status precedence (OOMKilled over CrashLoopBackOff when it caused the loop), how unassigned workloads are shown, version display during rollouts, sort modes, column-dropping order, `ctrl+p` deferred to M5.

## Acceptance criteria
- `huginn --demo` shows the 14 repos with the mockup's statuses within 1 s; about 90–130 s after start, payment-service goes Progressing then back to Healthy with version v2.14.4 without any key press.
- `ctrl+e` → prd shows the red header and PRODUCTION chip; switching back works; the status bar reports each switch.
- Filter, sort, navigation, Enter/Esc and `--repo` work as described; nothing overflows at 80×24.
- `go test ./...`, lint and the architecture test are green; CI green on the three OSes.
